# gentle-shell Agent Instructions

## Mandatory Codegraph Instructions

Codegraph comes first for every show, what, where, check, how, plan, refactor, code fix, analysis or investigation that needs symbol, structure or call-path discovery, run a codegraph query or explore BEFORE any read/fd/find/rg/grep search whenever the workspace has a .codegraph index. For every refactor, code fix, analysis or investigation, codegraph also precedes any rg/grep symbol search. rg/grep are for exact-string and filename lookups, or when codegraph fails or the index could not be initialized.

- Trust by calling, not by checking: never probe daemon state or test for a `.codegraph/` directory before the first codegraph call — index presence is answered by the call itself. The codegraph tool answers on its own (daemon, then CLI fallback) and is bounded; only a failed call, or one that returns no results for the question, is the signal to fall back to read/grep/find.
- Search-tool gate: codegraph gates the search tools — the session's first fd/find/rg/grep search must come after a codegraph query or explore, and once codegraph has been used for the investigation at hand, fd/find/rg/grep may be used freely for the rest of that investigation (exact-string, filename, or symbol); a new investigation re-arms the gate.
- Memory ordering: codegraph gates memory reads only within a prompt that searches the workspace — a search-tool call (grep, find or ls) or a bash command naming rg, grep, fd, find, ag or ack. In such a prompt, codegraph calls of the same step may run in parallel with each other, but every planned codegraph query or explore must have returned before any memory read, and a memory call is never issued in the same parallel block as a codegraph call; then, when memory tools are available, run mem_context and at least one task-scoped mem_search before proceeding further, even when codegraph failed or no index could be initialized. Memory reads in prompts with no workspace search are not gated.
- Post-compaction revalidation: after compaction or workspace changes, recover target, actor access, and preparation status before using graph evidence; history alone authorizes no init/sync.
- Index hygiene: keep .codegraph/ out of the change — `gentle-ai codegraph init` maintains the workspace's local git exclude (appending `.codegraph/` once; tracked .gitignore files are never edited) and the index ships its own .gitignore; never commit index files or hand-edit the exclude.
- Fallback: if codegraph fails, returns no results for the question, or the index could not be initialized, fall back to fd/find/rg/grep directly, and any search that ran without a preceding codegraph call names the skip reason in one line in the final report.
- Staleness: current source prevails over conflicting graph output — inspect the relevant stale files directly, or task-relevant source if the whole index is stale; graph output never replaces tests, compilers, linters, or runtime checks.
- Anti-redundancy: source returned by the graph counts as inspected; do not repeat reads or searches merely to confirm symbols when the required evidence is already present.
- Wrong-project guard: before trusting query/explore -p results for a path whose index you have not verified, run "codegraph status `<path>`" and assert its "Project:" line names that path — codegraph silently answers from the current project (exit 0) when the -p target has no .codegraph index, so the failure fallback never fires and wrong-project hits look identical to correct ones.
- Worktrees: codegraph is workspace-scoped; when a worktree is created, the parent checkout's .codegraph folder is copied into it — the complete folder (`codegraph.db` with its `-wal`/`-shm` sidecars) followed by one `codegraph sync` — because copying is faster than initializing from scratch; if the runtime already did it, there is nothing to do. init is for fresh projects without a parent index. Worktree commands run through the CLI with explicit path args: init/index/sync/unlock/status take a positional path and query/explore take -p, so no cd is needed.
- Subagents: a subagent that can call codegraph does so itself, and for a worktree dispatch it does so via the CLI path args because session-bound codegraph tools answer from the subagent cwd and not the dispatched worktree; when it cannot, the parent session runs the query BEFORE dispatching the subagent and embeds the findings in the task handoff, and a subagent result that claims codegraph verification must quote the query it ran or cite the parent-provided findings, otherwise the claim is treated as not performed.
- Truncation fallback (MCP variant): prevention first — a broad explore goes through the native session codegraph tool (daemon path, unaffected by Pi's 20 KB MCP cap), because a full-budget explore on this repo emits ~25 KB, over that cap; call mcp__codegraph__codegraph_explore only with a narrow query and maxFiles ≤ 4, or from a codemode script (untruncated). A middle-cut mcp__codegraph__* result — one carrying "Warning: truncated output" or "…N chars truncated…" — is never worked from: re-run the same query through the native session codegraph tool or read the result's [Full output: …] file with offset/limit; use the native tool when the whole report matters, the file when only a slice is missing.
