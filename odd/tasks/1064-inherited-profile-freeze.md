## Specs

- **S1 Freeze at startup.** "6.4 option A: a session that never pressed Enter resolves `p → P → G` ONCE at startup and freezes it (snapshot + origin)." "SCOPE BEFORE 3b-i = in-memory freeze, wired now (not unwired helpers). Same model as #1558's in-memory explicit binding: works now, lost on --resume until 3b-i adds persistence."
- **S2 Precedence, one resolver.** "Precedence for a launch: explicit session binding (Enter) → frozen inherited (startup) → live p → P → G only in `follow` mode. One resolution function used by launch, status and Usage (the single-rule requirement). Do not add an 8th ad-hoc resolver."
- **S3 Separate store, untouched contracts.** "Keep the frozen-inherited state in a SEPARATE in-memory store (own module, globalThis + Symbol.for like #1558). Do NOT modify lib/session-profile-binding.ts: Nox is rewriting it for 3b-i. If a change there becomes unavoidable, stop and flag it so the user can coordinate on #1064 first." "Do NOT change resolveProfilePin semantics (7+ call sites). Add a new function for the p→P→global resolution with origin."
- **S4 Global origin.** "GLOBAL ORIGIN = profiles.json `active` content (same source as Usage). This is a behavior change for unpinned sessions: today launch falls back to the materialized stores (gentle-agents.ts ~1453-1462). Call it out explicitly in the PR description and in docs. No `active` and no pin means "no profile": freeze nothing and keep today's behavior." User decision (L3): a session that starts with no profile freezes "no profile"; a later pin does not change it and the drift notice applies.
- **S5 Drift notice.** "Drift notice: on launch, re-resolve `p → P → G` only to compare. If it differs from the frozen profile, show one line ("pin changed to X, this session keeps Y, Enter to adopt"). Precisions approved by barbatdev: (a) once per change, not every launch; (b) only for inherited bindings, never after an explicit Enter; (c) Enter in `follow` mode makes the binding explicit." "'Once per change' memory in-memory, keyed by session plus the content hash of the current default. It reappears once after resume: accepted. Document it."
- **S6 `follow`.** "follow = env var now (GENTLE_PI_PROFILE_FOLLOW=1, check naming consistency with existing GENTLE_PI_* vars). Defer the Pi flag, since flags are per-extension. In follow there is no freeze and no drift notice. Enter makes the binding explicit." "Documented limitation: the orchestrator comes from the startup profile while children follow later defaults."
- **S7 Children.** "Children (GENTLE_PI_AGENTS_CHILD=1): never freeze, compare or warn."
- **S8 Footer.** "Footer: no new UI. The frozen inherited profile shows its existing origin label ((local)/(repo)) plus the global name as today. No "frozen" wording in this slice."
- **S9 Startup hook.** "Startup hook: prefer the parent-only path, and verify it runs for new sessions and resumed ones (`reason` is "startup" for --resume/--continue too). With an in-memory freeze, re-freezing on resume is acceptable for now; note it as a 3b-i integration point."
- **S10 Foreign repository.** User decision (L3): a launch to a foreign `repository_root` from a session with a frozen inherited profile uses the frozen profile, like an explicit binding (PRD §12 "Delegación a otro repo: gana el perfil de la sesión").
- **S11 Tests.** "freeze at start; pin/active changed from another session does not change the frozen session; drift notice shown once per distinct change and only for inherited bindings; no notice after Enter; follow re-resolves and has no notice; Enter in follow becomes explicit; children skip; no profile anywhere keeps today's behavior; launch/status/Usage agree."
- **S12 Process.** "ODD task file before the first write, new worktree and branch from fresh origin/main, test-first. Work-unit commits are fine; no push and no PR (#1064 still lacks status:approved; the user is asking barbatdev)."
