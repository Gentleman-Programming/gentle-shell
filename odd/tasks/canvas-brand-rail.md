# Canvas brand rail: implement design/canvas-chrome/03-brand-rail.html

Objective: restyle and restructure the Gentle Design canvas UI (`assets/design-canvas/`) after the chosen artboard `design/canvas-chrome/03-brand-rail.html`, with tokens from `design/system.md` (Brand set).
Branch: `feat/canvas-brand-rail` (base `main` a1c4ebc0b). Test runner: `node --experimental-strip-types --test tests/<file>.test.ts`; suite `pnpm test`. Work-unit commits only; push/PR are the user's decision.

## Specs

Source: L1. The artboard is the visual spec; map it to the existing canvas code, never copy its HTML verbatim. Every existing behavior (pan, zoom, fit, focus mode, Shift+Esc, comment mode, inspector picks, pins, popover with screenshot, Send now / Collect, Send all, open/resolved filter, handoff chips, Implement this with confirm, Compare view, toast, live reload, system board, design selector, empty state) keeps working, and existing tests keep passing unless a test pinned a markup detail this redesign deliberately changes (then update that test and say why).

- **S1 Brand tokens.** User: "Take colors, typography, spacing, radius and shadows from design/system.md, the project's token source." The canvas uses the Brand set of `design/system.md` (`assets/install-wizard/wizard.css` values: `--bg #1a1218`, `--bg-deep #000000`, `--surface #20161e`, `--surface-1 #241822`, `--surface-2 #342230`, `--border #342230`, `--border-soft #ffffff17`, `--text #f6eff3`, `--text-muted #a78e9b`, `--text-faint #76616b`, `--accent #f095c8`, `--accent-strong #ff76c3`, `--accent-soft #ffb1dd`, `--success #b4e7c7`, `--warning #e0c27a`, `--error #ff718f`, `--info #a9c7ee`, radius 8/12/16/999, `--glow`, `--shadow-panel`, `--font-sans` Inter stack, `--font-mono` Iosevka stack, focus outline 2px solid accent). No raw hex outside the `:root` token block (artboard iframe background `#fff` excepted). Local fonts only; no external URLs.
- **S2 Layout.** As in the artboard: a full-height left **tool rail** (60px, `--bg-deep`, brand mark "GD"), a **top bar** across the rest (56px, `--surface`), below it an **artboard navigator** column (240px), the **viewport** (dot grid of `--surface-2` on `--bg`), and the **review side** (360px). The navigator and the review side can be hidden; hiding gives the viewport the room.
- **S3 Icons.** Inline SVG icons (stroke, currentColor, Lucide-style) from one sprite in `index.html`; every icon-only button has an accessible name and a `title` naming its shortcut. No emoji icons.
- **S4 Rail tools.** Top to bottom: Navigate (V), Comment (C) as a pressed pair (Comment = the existing comment mode toggle; the active tool shows `aria-pressed="true"` and the accent indicator bar), separator, Fit all (F) ("Overview"), Artboard list toggle ([) controlling the navigator, Design system (focuses the system board; disabled when there is none), and Keyboard shortcuts (?) pinned at the bottom.
- **S5 Keyboard shortcuts.** `V`, `C`, `F`, `[`, `]` (review side), `?` (shortcuts dialog), plus the existing ones (`+`/`-`/`0`, arrows, Shift+Esc). Single-key shortcuts are ignored while typing in an input, textarea or select, while the popover is open, and in focus mode except Shift+Esc. A `<dialog>` lists them all.
- **S6 Artboard navigator.** Header "Artboards · N". One item per design artboard (system board excluded) with a thumbnail block, the title, a comment summary ("2 open comments", "1 resolved", "No comments"), and a tag "Chosen" (accent, with dot) or "Alternative" once a chosen artboard exists. The focused artboard item has `aria-current="true"`. Activating an item enters focus mode on that artboard. Footer note when a system board exists: "Design system board is always first in Overview."
- **S7 Top bar.** "Gentle Design / [design selector] / feature path" (the feature path as a mono code chip, hidden when the manifest has none), then on the right the zoom group (−, level, +, Fit), a "Compare with app" button (visible only when the chosen artboard is implemented with a valid loopback previewUrl; opens the existing Compare view for it), and the session status line with a status dot.
- **S8 Review side.** Tabs "Comments N" / "Resolved N" / "Brief" (the first two drive the existing open/resolved filter). Comment cards show the pin number badge, the selector as a code chip, a waiting/sent state, the text, screenshot thumbnail when present, and the existing actions. Brief tab shows the manifest title, brief and feature path. Footer: the send-mode segmented control ("Send now" / "Collect", the existing radios) and the full-width primary send-all button.
- **S9 Handoff timeline.** In the review side, for the chosen artboard: "Handoff · <title>" with steps Chosen → Sent to the session → In progress → Implemented; done steps use `--success`, the current step `--info`, pending steps `--text-faint` outline; timestamps from `sentAt`, `startedAt`, `implementedAt`; the In progress step shows the handoff note when present. Hidden when nothing is chosen.
- **S10 Mode chip.** The navigation-mode line becomes a floating chip in the viewport ("Navigating", "Click an element to comment · Esc", or the existing focus text), and the focused artboard header shows its number, title and handoff state chip.
- **S11 Accessibility.** WCAG AA contrast, visible focus on every control, `prefers-reduced-motion` respected, landmarks and labels kept.

- **S12 Readable errors.** User (L6/L7): "Mensajes legibles: traducir cada código a una frase con su causa y su salida." Every server reason code the canvas can receive (`batch-delivery-unavailable`, `implement-unavailable`, `delivery-failed`, `too-many-comments`, `too-many-handoffs`, `invalid-comments`, `invalid-handoffs`, `invalid-comment`, `invalid-handoff`, `invalid-screenshot`, `body-too-large`, `file-too-large`, `not-found`, `too-many-streams`, `internal`, other `invalid-*`) maps to an English sentence naming the cause and the way out; the raw code stays available as a small detail or `title`. Unknown codes fall back to a generic sentence plus the code. Example cause/way out: the canvas is not connected to a Pi session, comments stay saved, open it with `/gentle:design open`.
- **S13 Feedback next to the action.** "un aviso en el pie del panel, encima de \"Send all\", con icono, color de error y botón para cerrarlo. También para \"Implement this\" y para resolver o reabrir comentarios. Los éxitos seguirían saliendo como toast." Errors: Send all → alert in the review footer above the button; resolve/reopen → alert inside that comment card; Implement this → alert in that artboard's implement control; a toast repeats it only while the artboard is collapsed by zoom (L9), since the alert is hidden then. Alerts use `role="alert"`, an icon, `--error`, a dismiss button, and stay until dismissed or the next attempt. Successes show as the existing toast.
- **S14 Status line for canvas state only.** "la línea de estado de la barra superior quedaría para el estado del canvas (conexión de live reload), no para el resultado de tus acciones." Action results (send, send all, resolve/reopen, implement, comment saved) no longer write the top status line.
- **S15 Delivery capabilities up front.** "que el servidor avise al cargar si no hay sesión conectada, para desactivar \"Send all\" de antemano con esa explicación." The server's page config tells the canvas which deliveries exist (single comment, batch, implement). Without batch delivery, Send all is disabled and the footer explains why (S12 wording); without implement delivery, Implement this is disabled with the explanation. A request that still fails reports through S12/S13.
- **S16 Visual proof.** "cuando este vuelve a levantar el canvas para hacerle capturas": after implementing, restart the preview canvas and take screenshots of the new feedback states.
