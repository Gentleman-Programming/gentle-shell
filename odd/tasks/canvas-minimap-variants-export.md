# Canvas minimap, another direction and export: implement design/canvas-features/05-minimap-variants-export.html

Objective: a minimap to move around many artboards; an artboard menu with "Try another direction from this…" (asks the session for a new artboard based on that one) and PNG export via the browser's own tab capture. Visual spec: `design/canvas-features/05-minimap-variants-export.html`, with export per L2. Tokens: `design/system.md`.
Branch: `feat/canvas-minimap-variants-export`, after the queued canvas features (same files; one writer at a time). Work-unit commits only; push/PR are the user's decision.

## Specs

- **S1 Minimap.** User (artboard tradeoff): "faster navigation". A small panel in the viewport's bottom right shows every board (system board first) as a block at its relative position and size, the chosen artboard in accent, a placeholder being designed as a dashed block, and the visible area as an outlined rectangle. Clicking or dragging in it pans the canvas; `M` toggles it (same suppression rules as the other single-key shortcuts; listed in the shortcuts dialog). Hidden in focus and Compare. Its blocks are not individually focusable; the panel has an accessible name and the existing artboard list remains the keyboard path.
- **S2 Artboard menu.** User (artboard tradeoff): "the menu hides actions that were one click away". Each design artboard's header gets a `⋯` menu button (accessible name with the artboard title, `aria-haspopup="menu"`, `aria-expanded`) with: Try another direction from this…, Compare with app (when available), Export as PNG, Export as PNG at 2×, Implement this. Implement this stays visible in the header too, so it is not hidden behind the menu. Full keyboard menu behavior: arrows, Home/End, Enter, Esc returns focus to the button. The system board has no menu.
- **S3 Another direction.** The dialog shows the source artboard title, a text field "What should change?" (1–2000 characters), suggestion chips (More compact, Bolder, Mobile first, Calmer colors) that fill the field, Cancel and **Send to the session**. Sending posts to a new server route (same Origin/JSON/token rules and bounds as Implement) that sends the session one message asking the gentle-design skill to add the next artboard to that design based on the source file, keeping the others; queued as a follow-up while the agent is busy. The page config's `delivery` gains `variant`; without it the action is disabled with the S12-style explanation used for Implement. Until the manifest gains a new artboard, a placeholder board "<NN> · New direction" with state **Designing…** shows after the last artboard; it disappears when the manifest changes or after the canvas reloads.
- **S4 Export.** User choice (L2): "Captura de pestaña del navegador (recomendado)". Export uses `navigator.mediaDevices.getDisplayMedia` (preferring the current tab where the browser supports it), grabs one frame, crops it to the artboard frame's on-screen rectangle at 100% (the canvas temporarily focuses the artboard at 100% when needed and restores the view after), and downloads `<artboard-file-without-ext>.png` or `@2x.png` (2× uses the device pixel ratio or upscales and says so). The stream is stopped right after the frame. If the API is missing or permission is denied, an inline alert explains it and suggests the browser's own screenshot tool. No "Export all". No server involvement; nothing is written under `design/`.
- **S5 Docs, accessibility, tests.** `docs/gentle-shell.md` and the skill describe the minimap, the menu, the variant flow (the skill's "Save and try a different approach" gate covers the message) and export with its browser limits. WCAG AA, visible focus, reduced motion; tokens only from `design/system.md`. Tests cover minimap geometry and panning, menu keyboard behavior, the variant route (validation, Origin, delivery, queued) and dialog, the capability flag, and export with a mocked `getDisplayMedia` (success, denied, missing).
