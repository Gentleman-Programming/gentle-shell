# Canvas mix: combine what the user likes from several artboards into a new direction

Objective: from the canvas, pick elements of several artboards, choose a base artboard, and ask the session for one new artboard that combines them.
Branch: `feat/canvas-mix` (from local `main` after merging canvas-chosen-direction and canvas-check-highlight). Work-unit commits only; push/PR are the user's decision.

## Specs

- **S1 Add to the mix.** User-approved proposal (verbatim, L2): "Marcar lo que te gusta. En modo Comentar, el popover tendría una segunda acción además de «Comentar»: «Añadir a la mezcla», con una nota opcional («me gusta la cabecera», «solo los colores de las tarjetas»). Si eliges un contenedor, te quedas con la sección entera; si eliges un elemento, solo con ese." A pick records the artboard file, selector, excerpt and optional note (the same fields a comment has, bounded the same way).
- **S2 Mix tray.** (verbatim, L2): "Una bandeja «Mezcla». Sería una pestaña del panel derecho con lo seleccionado agrupado por propuesta, por ejemplo «01 · cabecera», «02 · gráfico semanal», «03 · barra lateral». Cada selección se puede quitar, y en el canvas lleva un pin de otro color." The tab shows its count; an empty tray explains how to add picks. Picks live in the canvas (kept per design in the browser's `localStorage`, key `gentle-design:mix:<slug>`, like the language choice), survive artboard reloads, and are dropped for picks whose artboard no longer exists.
- **S3 Base.** (verbatim, L2): "Elegir la base. Un selector «Estructura de: 01 / 02 / 03» indica qué propuesta aporta el esqueleto de la página, porque sin base el agente tiene que inventarlo." Defaults to the artboard with the most picks (first on a tie).
- **S4 Create.** (verbatim, L2): "«Crear propuesta combinada». Envía a la sesión un único mensaje con la base, las selecciones (artboard, selector, texto y nota) y la regla de usar los tokens de `design/system.md`. El agente escribe un artboard nuevo, `04-mezcla-….html`, sin tocar los otros, y el canvas se refresca solo. Las selecciones quedan marcadas como usadas." Server: `POST api/designs/<slug>/mix` with `{ base, picks: [{ file, selector, excerpt, note }] }`, same guards as `variant` (own Origin, JSON body, bounded lengths, base and every pick file must be artboards of the manifest, 1..20 picks), delivered through a new `onMix` option (501 `mix-unavailable` without it; `delivery.mix` in the canvas config so the button is disabled with a reason up front, as S15 does for other deliveries); 202 `{ ok, slug, queued }`. The message is built in lib/gentle-design.ts (`planDesignMix`/`designMixMessage`, English agent instructions like `designVariantMessage`), and extensions/gentle-design.ts wires it like `onVariant`. After a successful send the picks are marked used (shown as used, cleared by a "Clear used" action or the next pick) and a toast says Queued/Sent.
- **S5 Skill.** skills/design/SKILL.md Decision Gates gets a row for a canvas message "Combine artboards of the design …": write the next `NN-mix-<name>.html` starting from the base artboard's structure and bringing in each picked element, append it to the manifest with a tradeoff naming its sources, keep every other artboard untouched.
- **S6 Docs, i18n, a11y, tests.** Every new canvas string in both catalogs (EN/ES, neutral Spanish, tú forms); docs/gentle-shell.md (Gentle Design section) and the README Gentle Design row mention Mix; tokens only; keyboard reachable; tests: server route validation and delivery (tests/design-canvas-server.test.ts), message (tests/gentle-design.test.ts), canvas through the fake DOM (tests/design-canvas-assets.test.ts).
