# Canvas screen sizes and live thumbnails: implement design/canvas-features/01-screen-sizes.html

Objective: in the Gentle Design canvas (`assets/design-canvas/`), preview one artboard at phone, tablet, desktop or a custom width, alone or all sizes side by side, and show live thumbnails in the artboard list. Visual spec: `design/canvas-features/01-screen-sizes.html`; tokens: `design/system.md`.
Branch: `feat/canvas-screen-sizes` (base `feat/canvas-brand-rail` at the design commit). Test runner: `node --experimental-strip-types --test tests/<file>.test.ts`; suite `pnpm test` (4 tests in `tests/agent-home.test.ts` fail on `main` on this machine too). ## Specs

Source: L1 (handoff) and the artboard. Wording outside quotes is the parent's reading of the artboard.

- **S1 Size control.** User (artboard tradeoff, L1): "see one artboard at phone, tablet and desktop widths side by side". While an artboard is in focus mode, its header shows a size control: **Phone** 390 × 844, **Tablet** 820 × 1180, **Desktop** (the artboard's own manifest size), **All sizes**, and a custom width field (whole CSS px, 240–2560; height keeps the artboard's manifest height). Desktop is selected when focus mode starts. The current size reads as `<width> × <height>` next to the control. Every control has an accessible name and visible focus.
- **S2 One size at a time.** Phone, Tablet, Desktop or a custom width resize the focused artboard's iframe to that width (and the preset height), at 100% like today's focus mode, centered; a size wider than the viewport keeps today's behavior for wide artboards (start at the left margin). Leaving focus mode restores the manifest size. The artboard reloads nothing: only the iframe size changes, so the design's own CSS media queries respond.
- **S3 All sizes.** Shows Phone, Tablet and Desktop of the focused artboard side by side, each scaled down to fit the viewport together, each labeled with its icon, name, `<width> × <height>` and scale (`· 50%`). Each is a real artboard iframe at its true width, so media queries apply.
- **S4 Comments at every size.** Comment mode works on the focused artboard at any size and in All sizes (each size frame takes picks), and the pins of that artboard show on every size frame at their element's position in that frame.
- **S5 Overflow flag.** When the artboard's page is wider than the frame at a given size (horizontal overflow), that size shows a warning chip "Overflows" with a title explaining that content is wider than `<width>` px. No chip when it fits.
- **S6 Live thumbnails.** Each item of the artboard list shows a scaled-down live render of its artboard instead of the CSS placeholder: a sandboxed iframe (`allow-scripts` only, like the artboards) that is inert, hidden from assistive technology, never focusable and never takes pointer events; it reloads when the artboard file changes.
- **S7 Size on comments.** A comment created while the artboard is shown at a size other than its manifest size records that size as an optional `viewport` field `{ "width": <int>, "height": <int> }` in `comments.json` (validated: integers 240–4096 / 1–20000; absent otherwise; files without it stay valid). The comment card shows it (for example `Phone 390 × 844` or `720 × 820`), and the message sent to the session names it so the agent edits for that width. The `gentle_design_comments` tool and the skill's file-format section describe the field.
- **S8 Docs and accessibility.** `docs/gentle-shell.md` describes sizes, All sizes, overflow and thumbnails; the skill documents `viewport`. WCAG AA, visible focus, `prefers-reduced-motion` respected; tokens only from `design/system.md`.
