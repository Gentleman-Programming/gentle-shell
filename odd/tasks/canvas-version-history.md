# Canvas version history and agent replies: implement design/canvas-features/02-version-history.html

Objective: keep earlier versions of every artboard, compare any version with the current one (slider or side by side) and restore it; show what the agent did for each applied comment. Visual spec: `design/canvas-features/02-version-history.html`; tokens: `design/system.md`.
Branch: `feat/canvas-version-history`, started from `feat/canvas-token-inspector` (d01dcd4d1) after screen sizes and the token inspector closed (same files; one writer at a time). Test runner as in `odd/tasks/canvas-screen-sizes.md`. Work-unit commits only; push/PR are the user's decision.

## Specs

Source: L1 (handoff) and the artboard. Wording outside quotes is the parent's reading; defaults marked (default) are parent decisions the user may change.

- **S1 Snapshots.** User (artboard tradeoff): "compare and restore any earlier version". Whenever an artboard file of a design changes on disk (agent edit, hand edit, restore), the canvas server stores the previous content as a version under `design/<slug>/.history/<artboard-file>/<n>.html` with an index (`design/<slug>/.history/index.json`: per artboard, ordered versions with `n`, `createdAt`, `source` = `agent` | `hand` | `restore`, optional `comment` id and `note`). The first time an artboard is seen, its content is v1. Identical content is never stored twice. (default) At most 50 versions per artboard; the oldest beyond that are dropped, never the current one. Writes are atomic and never follow symlinks or leave `design/`; a corrupt index is reported and left untouched, like `comments.json`.
- **S2 History tab.** The review side gains a fourth tab, **History** (with its count), next to Comments and Resolved. It lists the selected artboard's versions newest first: `v<n>` with **Current** on the newest, who (Agent / You / Restore), short time, the applied comment number when there is one, and the agent's reply (S5). Actions per older version: **Compare with current** and **Restore**; the current one has **View**.
- **S3 Compare versions.** Comparing shows the older version and the current one over the artboard with a draggable slider (keyboard: arrow keys move it; it has an accessible name and value), labeled `v<n> · <time>` and `v<current> · Current`, plus a **Side by side** mode and **Close comparison**. Version files are served read-only by the canvas server under the same token, Host and path rules as artboards, in iframes sandboxed `allow-scripts` only.
- **S4 Restore.** User (artboard): "Restore saves the current one first, so nothing is lost." Restore asks for confirmation, writes the chosen version's content to the artboard file (which itself creates a new version with `source: restore`), and the canvas reloads it. Restore is refused for files outside the manifest and needs the server's own Origin like every write.
- **S5 Agent replies.** User (artboard): "each applied comment shows what the agent did". Resolving a comment can carry a short note (`gentle_design_comments` `resolve` gains an optional `note`, at most 500 characters; stored as an optional `resolution` field on the comment). The Resolved tab and the matching version in History show it as **Agent:** `<note>`. Comments without it stay valid. The skill tells the agent to write one line about what it changed.
- **S6 Docs, accessibility, tests.** `docs/gentle-shell.md` and the skill describe history, restore, retention and `.history/`; WCAG AA, visible focus, reduced motion; tokens only from `design/system.md`. Tests cover snapshot creation, dedupe, retention, restore round trip, refusal paths, the served version routes and the UI.
