# codegraph-windows-perf

Fix the seven Windows performance findings (F1-F7) from the 2026-11-18 review of codegraph usage in gentle-shell. The index engine itself is the external `codegraph` binary; this feature removes the gentle-shell-side multipliers around it: cmd.exe shim spawn chains, per-query sync, realpath chains, sync-FS lease churn, sequential worktree seeding, machine-wide pipe enumeration, and blocking warm-up. Baselines and acceptance targets come from the VM battery (see Log L3). Verification per unit: RED test first, focused suite, `pnpm typecheck`.

## Specs

S1: "review windows performance when using codegraph. report any issue to fix them" — review delivered 2026-11-18, read-only. Findings F1-F7 with path:line anchors live in tmp/explorer-windows-perf-map.md and memory topic `codegraph-windows-perf-review` (obs 4558). Scope of this feature is exactly those seven findings; the external binary's internals (INIT walk, parsing, hashing) are out of scope.

S2: "detailed plan to fix the 7 issues" — this document is that plan. Implementation starts only on explicit go-ahead; branch decision recorded in Log.

S3 (F1): every win32 CLI call currently spawns cmd.exe + npm `.cmd` shim as a `shell:true` string (lib/codegraph-readiness.ts:179-183, buildWindowsCommand :167-175), and the MCP tool runner adds an ENOENT per-PATH-entry rescan (extensions/codegraph-tools.ts:562-596). Fix: resolve the shim's node entrypoint once per process (fail-closed to the existing cmd.exe string when the shim shape is unknown), then spawn `node <entry> <args...>` directly with an arg vector — no shell, no cmd quoting, no `%`-rejection on the direct path. Measured relevance: UNC STATUS ×14.2 multiplier, WT_INIT 34.5s.

S4 (F2): `awaitSearchSync` runs before every query when the daemon path is unavailable (extensions/codegraph-tools.ts:588-594), paying full CLI startup + sync walk per query (UNC QUERY ×5.1; incr sync 2.13s). Fix: per-root freshness window (constant, 60s default) — consecutive queries within the window issue no `sync -q`; a failed sync never counts as fresh.

S5 (F3): `canonicalRoot`/`realpathSync.native` runs per daemon record per call (lib/codegraph-daemon.ts:49-52), per lease op (lib/codegraph-lease.ts:44-46), and per prompt in resolveWorkspaceCwd (extensions/codegraph-tools.ts:201-224) — each is an SMB round-trip chain on UNC. Fix: process-lifetime memoization of canonical forms (test-clearable), reused by the daemon registry, lock-path computation, and the workspace guard.

S6 (F4): sync-FS lease/mutex churn — `wx` write + `statSync` + 5ms `Atomics.wait` loop with mutex create+rm per section (lib/codegraph-lease.ts:344-481) and lock reads + `process.kill` probes per verdict (:129-215). Fix: async waits on async paths, no `statSync` on the uncontended fast path, verdict reuse within one composite operation. BLOCKED: lib/codegraph-lease.ts + tests carry in-flight uncommitted concurrent-session work; re-read current state before designing.

S7 (F5): worktree seed runs 3 sequential CLI startups (two `files --format flat -j` listings + `sync -q`, lib/codegraph-readiness.ts:727-760) plus single-threaded sqlite `VACUUM INTO` (lib/codegraph-seed.ts:185-215) — WT_INIT 34.5s win vs 15s mac. Fix: one listing where the two are semantically identical (verify first), direct spawn via T1's resolver, and phase timing markers (SEED_SNAPSHOT_MS / SEED_SYNC_MS log lines) so the battery can measure phases. BLOCKED: in-flight uncommitted seed work + depends on T1 (same file readiness.ts).

S8 (F6): win32 daemon liveness enumerates every named pipe on the machine (`readdirSync("\\\\.\\pipe\\")`, lib/codegraph-daemon.ts:78-88) per check. Fix: short-timeout connect probe (250ms) on the daemon's own pipe with cached positive result; preserve current failure semantics (probe failure counts as present).

S9 (F7): the daemon-death query path can stack attempt → warm (up to 120s; "a cold daemon on a network share can need over a minute", lib/codegraph-readiness.ts:33-34,196+) → attempt → CLI (extensions/codegraph-tools.ts:522-537,586-640). Fix: never block the query on warm-up — trigger warm-up in background and fall through to the CLI query immediately; skip the second daemon attempt after a fast warm failure; honor DAEMON_SKIP_MS.

S10: verified non-issues stay non-issues — this work introduces no per-file stat loops, no fsync, no tasklist/powershell liveness, no per-file process spawns, and no `\\?\` long-path handling.
S11: "add win32 conditional to this fixes" — every behavior change in T1-T5 is gated behind a win32 platform conditional (`process.platform === "win32"`): on POSIX the existing code paths keep their current behavior byte-for-byte (spawn stays the plain arg-vector spawn, socketPresent keeps its current check, the query flow keeps its current sync/warm order, lease/seed behavior is unchanged). The direct-spawn resolver is consulted only on win32. Tests cover both branches: win32-gated activation and POSIX passthrough. Purely additive logging (SEED_*_MS markers, T5) stays cross-platform so the VM battery can measure all rigs.
