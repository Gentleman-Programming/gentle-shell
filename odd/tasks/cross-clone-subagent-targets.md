# Authorized cross-clone subagent targets

## Objective and problem
Let a Pi session explicitly launch a bounded subagent in an independent Git repository without changing the parent's cwd or treating that repository as a linked worktree. Following the user's explicit scope change to align with issue #1286, `workspace_root` stays same-clone-only; a new mutually exclusive `repository_root` selects an independent repository with live interactive consent. Authenticated foreign child mutations must be attributed to the target repository without registering it in the parent's same-clone Changes worktree registry.

## Scope and constraints
- Work only in the isolated `feat/cross-clone-subagent-targets` worktree; preserve both repositories' existing worktrees and unrelated changes.
- Keep `SessionWorktreeRegistry.validate/register` same-clone-only for linked worktree entries, footer/widget counts, and ordinary Changes attribution. A foreign child must not register its root there. Foreign Changes may be shown in the parent session only as separately authenticated, target-bound observed mutations, never as a linked worktree or forged model prose.
- A foreign destination must be an explicit existing canonical Git worktree. Resolve the canonical root and Git common directory from Git, not from model prose, a path alias, or inherited `GIT_*` routing.
- Obtain an interactive human grant before any queue or child session-directory write. Bind the grant to the live session identity and the destination's canonical Git common directory. The user chose one grant per foreign clone for the current session; later launches in that same live session may reuse it. No UI, cancelled/declined consent, missing/changed identity, or a new session fails closed. A reload that loses the live grant must fail closed rather than silently recreate it.
- Do not allow task text or tool arguments to mint a grant. `repository_root` and `workspace_root` are mutually exclusive; headless/RPC/child-originated foreign launches and foreign SDD/remediation fail closed. Same-clone behavior and existing SDD/remediation/review guards stay intact. Keep child cwd and model-profile selection bound to the validated destination. Delegation consent grants neither review nor delivery permission.
- No push, PR, merge, or release is authorized for this feature by the present request.
