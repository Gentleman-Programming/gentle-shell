# Desktop RPC: expose cross-session usage stats over Desktop RPC

Implements #3325 on branch `feat/desktop-rpc-usage-stats`. Delivery: single PR closing #3325. Test runner: `node --experimental-strip-types --test` (`pnpm test`), plus `pnpm run typecheck`.

## Specs

- S1 (#3325, Proposed outcome, verbatim): One read-only Desktop RPC method over the same loader and aggregation the TUI uses:
- S2 (#3325, Proposed outcome, verbatim): `get_usage_stats { range?: "7d" | "30d" | "all" (default "7d"), scope?: "project" | "all" (default "project") }` → `{ range, scope, totals: { sessions, messages, inputTokens, outputTokens, cacheReadTokens, cacheWriteTokens, cost }, byModel: [...], byDay: [...], byProject?: [...] }`. The ranges and scopes are exactly the ones `aggregateStats` supports, so the TUI and RPC never disagree.
- S3 (#3325, Proposed outcome, verbatim): Bounded arrays (models ≤ 50, days ≤ 400, projects ≤ 50, with `truncated`). Projects appear as display names, never paths. No session ids, no message text.
- S4 (#3325, Proposed outcome, verbatim): Reads go through the loader's size/mtime cache and run asynchronously; concurrent requests share one load. `stats_unavailable` when no session root can be read.

- L3 (T1 writer, decisions): the issue's response fields were mapped onto what `aggregateStats` really computes, without inventing numbers. `totals.messages` is the sum of the per-model `messages` counts (the aggregate counts usage records per model, not a separate total). `totals.totalTokens` was added because the aggregate's `total` (a record's own `totalTokens`, else the sum of its parts) is what `byModel.tokens`, `byDay.tokens`, and `share` are measured in; without it a client cannot reconcile those. `byModel` rows are the aggregate's `{model, messages, tokens, cost, share}`. `byDay` rows are `{day, tokens}` because the aggregate keeps only tokens per day; the newest 400 days are kept. `byProject` is not computed by `aggregateStats`; it is emitted only for `scope: "all"` and each row is `aggregateStats` run over that project's sessions with `scope: "project"`, keyed by working directory and shown as the last path segment (two directories with the same last segment stay two rows; the cwd only breaks sort ties and never reaches the wire). `truncated` is an object with one boolean per array (`byModel`, `byDay`, `byProject?`). Model ids and project names are cut at 128 characters. Explicit `null` for `range`/`scope` is `invalid_request` (only an omitted key takes the default).
