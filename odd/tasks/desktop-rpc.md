# Gentle Desktop RPC extension

Objective: implement `gentle-shell.desktop-rpc/v1` entirely through Gentle Shell's public extension API so Gentle Desktop can use structured commands, responses, snapshots, and events without parsing TUI text.
Branches: tracker `feat/desktop-rpc-tracker-01a1ccb1`; slice 1 `feat/desktop-rpc-transport-01a1ccb1`; base `origin/main@34a3c15c8ac88ca5823997e972f4b1ca8c1e1227`; delivery: user-selected feature-branch-chain, local work-unit commits only until separate publication authorization.
Runners: focused `node --experimental-strip-types --test tests/desktop-rpc*.test.ts`; typecheck `node scripts/check-types.mjs`; suite `pnpm test`; real-runtime maintainer probe for the slash-command transport.
Task Size: large (multi-slice contract, external Desktop/gentle-stream integration, and a real-runtime transport proof that cannot be resumed safely from a compacted diff alone).
Risk: item 1 (validated writes to existing configuration stores), item 2 (permission control and credential redaction), item 4 (correlated concurrent requests and ordered events). Each high-risk unit requires independent verification.

## Specs

S1. Implementation authorization (verbatim): "ok dale hagamos todo eso para que la app de gentle desktop pueda trabajar bien".
S2. Ownership constraint (verbatim): "creo que eso agregfaría una capa de abstraccion adicional a gentle-shell y que es dificil de mantener para cuando la gente que hace pi cambie cosas, entonces creo que poder extenderlo simplemente de nuestro lado". No fork, runtime source changes, dependency patches, or `node_modules` edits.
S3. Transport: one `registerCommand` entry point, `/gentle:desktop <json>`, with schema `gentle-shell.desktop-rpc/v1`, caller-supplied `requestId`, method params, typed errors, and responses/events emitted as JSON through the dedicated `gentle-desktop-rpc` `setWidget` channel. RPC-only activation; no TUI behavior change.
S4. Methods: `capabilities`, `get_snapshot`, permission get/set, allowlisted config get/set, subscription usage get/refresh, design canvas snapshot, subagent list/cancel, and job list/cancel. Reuse existing owners; do not create parallel stores, fetchers, registries, or process managers.
S5. Events: `permission_mode_changed`, `config_changed`, `rate_limit`, `design_canvas`, `agents_update`, and `jobs_update`. Event sequence numbers plus on-demand snapshots permit recovery. Existing `gentle-agents.activity/v1` remains compatible.
S6. Configuration safety: Desktop uses store identifiers, never physical paths. Validate every write, use atomic owner APIs where available, require `expectedRevision` for mutable stores, and expose derived/materialized stores as read-only. No arbitrary paths, arbitrary `!cmd` evaluation, credentials, auth tokens, or raw provider errors cross the contract.
S7. Permission safety: session changes take effect without restart through the existing session owner; optional persistence is explicit. The control method is never registered as an agent-callable tool.
S8. Provider truthfulness: ChatGPT/NaN refresh may reuse existing source implementations. Anthropic windows remain pending until provider headers arrive; no invented Claude endpoint or usage values.
S9. Cancellation: subagent/job cancellation calls the existing owner, uses public IDs, and handles already-terminal work without a race-driven error.
S10. Music: Gentle Desktop should use `gentle-stream ctl status --json`, `ctl volume … --json`, and `ctl mood … --json`; no private socket, Python HMAC helper, or duplicate Pi music manager. External implementation is limited to available authorized checkouts and dedicated worktrees.
S11. Delivery selection (verbatim): "Cadena con rama tracker (recomendada)". Each child slice is a cohesive work unit with tests/docs, forecast at roughly 400 authored changed lines or fewer where honest. No push, PR creation, merge, auto-merge, release, or current-session activation is authorized by this document.
S12. Verification: test-first for deterministic behavior, including focused RED/GREEN, malformed requests, correlation, error envelopes, lifecycle/reload, snapshots, capability discovery, and an actual installed-runtime JSONL probe proving slash-command dispatch and measuring session-history effects. No claim of Desktop compatibility without its client integration or a documented adapter contract.
