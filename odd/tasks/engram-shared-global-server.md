# Engram shared global server

Objective: bundled Gentle Shell shares the global Engram server like other agents' hooks, starting it when nothing listens, instead of private session-owned servers.
Branch: fix/engram-352-session-owned-pin (worktree .worktrees/engram-352-pin). Delivery: ask-on-risk. Test runner: `node --experimental-strip-types --no-warnings --test <files>`, full suite `npm test`.

## Specs

- S1. User (verbatim): "que lo obliguemos al user a levantar el server? en todos los otros agentes, el hook levanta el server si no esta levantado, porque no podemos hacer lo mismo?" When nothing listens on the default endpoint `127.0.0.1:7437` and no explicit Engram selection exists, Shell starts the verified bundled core as `engram serve` (default port, default data dir `~/.engram`), detached so it outlives Pi like other agents' hooks, waits a bounded time for `GET /compatibility` to satisfy `isReadyCompatibility`, then launches Pi with the existing reuse environment (guard as `ENGRAM_BIN` + `ENGRAM_URL=http://127.0.0.1:7437`).
- S2. User (verbatim): "pero porque un servidor privado? comparte el global papu". The bundled path no longer requires session-owned capabilities: remove the session-owned gate and `ENGRAM_PRIVATE_REQUIRED_NOTICE` route from startup; the bundled launch never selects `ENGRAM_SERVER_MODE=session-owned`.
- S3. An existing store at `~/.engram` (Shell-provisioned or foreign, e.g. created by the global CLI) no longer disables memory by itself: with nothing listening, S1 applies. Exception (assumption, keeps the existing tripwire): if `engram.db` header `user_version` is greater than the bundled core schema, do not start a server; memory stays disabled with a clear notice.
- S4. A server already listening that answers `/compatibility` ready is reused unchanged (existing). A listener that does not verify (other service, 401 token, 404/older server, malformed, timeout) keeps memory disabled with the existing notices; Shell never kills or replaces it.
- S5. If the spawn fails or readiness does not arrive within the bound, memory is disabled for that launch with a notice; Shell still starts. Concurrent launches racing to start the server converge: a failed bind followed by a ready `/compatibility` counts as success.
- S6. Explicit `ENGRAM_*` selections and invalid `ENGRAM_STARTUP_POLICY` keep their current behavior (never probed, never spawned). `--version`/help flags never probe or spawn.
- S7. Pins: Engram core 3.5.2 (already bumped). Companion stays on the proven `npm:gentle-engram@0.4.2` (URL reuse needs no session-owned support); revert the 0.5.0 pin.
- S8. Windows: the detached spawn uses `windowsHide: true`, `stdio: "ignore"`, `detached: true`, `unref()`, a clean env (no `GH_TOKEN`/`GITHUB_TOKEN`, `ENGRAM_NO_UPDATE_CHECK=1`), and the verified core path (`engram.exe`).
- S9. Docs and help (`docs/bundled-install.md`, `docs/readme-reference.md`, `gentle-shell --help`) describe the shared-server model; remove claims that require session-owned servers or a Shell-provisioned identity for memory.
