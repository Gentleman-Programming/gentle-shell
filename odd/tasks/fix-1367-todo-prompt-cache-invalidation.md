## Objective

Eliminate volatile per-turn stale counter mutations from the system prompt block generated by `todoPromptBlock`, restoring byte-for-byte prefix cache stability across consecutive turns when todo task state is unchanged, while preserving operator-visible staleness in the TUI card (`renderTodoCard`).

## Problem

In `extensions/gentle-todo.ts`, `before_agent_start` increments `current.turn += 1` on every turn and passes `staleTurns(current.state, current.turn)` to `todoPromptBlock(current.state, stale)`. When tasks remain open for >= 2 turns, `todoPromptBlock` appends `\n(stale: ${stale} turns without an update — bring the list up to date now)`.

Because the system prompt resides at the head of the context, this 1-character/turn increment invalidates prefix caching on every turn from turn 2 onwards (e.g. SGLang, vLLM RadixAttention, Anthropic Prompt Caching, DeepSeek). Long sessions (100k-300k tokens) suffer full uncached prompt re-prefill on every turn.

## Scope

In:
- `lib/shell-todo.ts`: Remove the volatile `staleLine` from `todoPromptBlock`. Retain `_stale?: number` in the signature for backwards compatibility. Keep `staleTurns` and `renderTodoCard` intact for operator TUI visibility.
- `extensions/gentle-todo.ts`: Pass `current.state` to `todoPromptBlock(current.state)`.
- `tests/shell-todo.test.ts`: Update `todoPromptBlock` expectations and add tests verifying byte-exact prompt determinism regardless of stale turns.
- `tests/gentle-todo.test.ts`: Add multi-turn cache stability test proving `before_agent_start` produces identical `systemPrompt` across consecutive silent turns while the TUI widget correctly reflects staleness.

Out:
- Changes to `staleTurns` calculation or `renderTodoCard` TUI rendering.
- Any change to `todo` tool parameters or execution logic.
