## Specs

The Spanish quotations below are exact fragments of the design accepted by the user, not newly attributed user-authored requirements. Implementation details outside them are labeled decisions or assumptions.

- S1 — Approved scope: "La propuesta es un centro de trabajos, no otro orquestador." "Un objetivo que puede sobrevivir a la sesión que lo ejecuta." "Trabajo ≠ sesión ≠ subagente." A durable work has stable identity, title/objective, explicit clone identity, optional branch/worktree/session, explicit status/summary and optional ODD reference. Linked worktrees share a clone; unrelated clones do not. Check public operations with real Git clone/worktree fixtures and reload from disk.
- S2 — Explicit work status versus observed session activity: "Estado del trabajo: pendiente, en curso, bloqueado o terminado. Se cambia explícitamente." "Actividad de la sesión: ejecutando, en espera, no conectada o desconocida. Se obtiene del runtime." "Esto evita errores como mostrar un trabajo terminado porque su proceso dejó de existir." Activity must never be inferred from work status, PID, stale presence or a saved timestamp. Show last observation when available; unknown is truthful when current activity cannot be established.
- S3 — Approved actions: "Crear un trabajo y vincular la sesión actual." "Ver objetivos, estados, ubicación y última actividad." "Consultar el último resumen y la referencia ODD." "Cambiar el estado o actualizar el resumen explícitamente." "Localizar la conversación vinculada, aunque ya no esté activa." Session navigation is bounded by verified Pi APIs; showing the exact stored session locator is acceptable and must not claim the session is live or resumable without validation. The command appears in the existing palette only when registered. Update command help and docs. Check through the registered command/TUI harness, including cancel/no-op paths.
- S4 — Persistence and safety: "Registro durable: conserva los datos del trabajo localmente, fuera de los archivos versionados del proyecto." "Una lectura fallida nunca debería sobrescribir el registro ni presentarlo como vacío." "Las pruebas cubrirían además escrituras concurrentes, datos inválidos y compatibilidad Windows/POSIX." Checks: public rejected operations leave stored records and revision/counters unchanged; concurrent public updates cannot lose accepted writes; invalid/malformed/unreadable records are explicit errors, not empty results. No automatic destructive lock recovery.
- S5 — Boundaries: "El registro no concede permisos, no bloquea archivos ni garantiza exclusividad de escritura. Tampoco reemplaza los documentos ODD ni convierte Engram en requisito." "Sin agentes automáticos, creación de worktrees ni dependencia de herdr." Registry locks protect only registry updates, never project files. New UI must not silently alter existing session routing, profiles or child lifecycle.
- S6 — Acceptance journey: "Tres trabajos, en distintas ramas del mismo repositorio: reiniciás Shell y podés reconocerlos, saber dónde quedaron y encontrar sus conversaciones, sin reconstruir todo manualmente." Validate reload with three works across one clone's worktrees, absent sessions and removed worktrees. Missing locations preserve work records and display uncertainty; no auto-spawn or cleanup.
