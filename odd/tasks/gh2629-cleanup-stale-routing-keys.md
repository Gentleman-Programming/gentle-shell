# gentle-shell#2629: user-initiated cleanup of stale routing keys

Add a user-initiated action to the /gentle:models (unified /gentle:profiles) panel that removes stale, unmatched routing keys from `subagents.json`, `models.json`, and every profile in `profiles.json`, never touching the live provider review roles.

## Specs

S1. "Lists every routing key, across `subagents.json` `model_profiles`, `models.json`, and each profile in `profiles.json`, that has no agent definition discoverable from the current workspace (project + global), reusing the existing `unmatchedProfileKeys` comparison." (issue #2629, Proposed outcome)
S2. "Unconditionally excludes the provider review roles (`PROVIDER_REVIEW_ROLES`: `review-refuter`, `review-validator`) from the candidate list, since those keys are live routing targets with no agent file by design (see #2430) and must never be offered for removal." (issue #2629)
S3. "Lets the user select which of the remaining stale keys to delete, and only deletes the ones explicitly selected, across all three stores, atomically, with no automatic or implicit deletion anywhere else (startup, sync, or save)." (issue #2629) — L4 supersedes L2: prepare all affected file replacements before mutation; compensate runtime failures by restoring original bytes/existence, report original and restoration failures, retain recovery copies if restoration fails. Reject linked files before mutation and detect changed inputs rather than overwrite them. Preserve existing legacy-model materialization behavior. This is runtime compensation, not crash recovery, power-loss atomicity, or isolation from uncooperative external writers.
S4. Out of scope: do not change the startup warning (`extensions/gentle-agents.ts`) or the panel's existing "unmatched" notice strings (`routingScreenNotices`) — that surface is already claimed by another contributor for issue #2430. Only add the new opt-in cleanup action and its own write path. Refresh existing notices after successful cleanup without changing their wording.
S5. Keep each PR ≤400 changed lines (chained-pr skill): PR1 is pure lib logic + unit tests (no UI); PR2 wires PR1's functions into the TUI panel + its own tests.
S6. Maintainer review on PR #2631 (Alan-TheGentleman, CHANGES_REQUESTED, 2026-11-06), verbatim: "1. prepareCleanup builds its known-agent list with discoverAgents(roots), which only scans <agentHome>/{agents,subagents} and .pi/{agents,subagents}. The panel itself uses listDiscoverableAgents, which also covers ~/.agents, <cwd>/.agents and the bundled pi-subagents agents. A route for e.g. worker or a .agents-only agent would be offered as stale and deleted. Please reuse the panel inventory and add a test with an agent that lives only in one of those roots. 2. #2629 asks for the removal to be atomic across the three stores, but the write path stops at the first failure without rollback. Please snapshot and restore earlier stores on failure. The branch also needs a rebase on the current #2630 head (8f0d16e) and main." #2630 has since been squash-merged into main as dd37ffe55, so rebase onto upstream/main.
