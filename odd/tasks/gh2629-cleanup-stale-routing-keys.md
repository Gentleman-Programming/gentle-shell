# gentle-shell#2629: user-initiated cleanup of stale routing keys

Add a user-initiated action to the /gentle:models (unified /gentle:profiles) panel that removes stale, unmatched routing keys from `subagents.json`, `models.json`, and every profile in `profiles.json`, never touching the live provider review roles.

## Specs

S1. "Lists every routing key, across `subagents.json` `model_profiles`, `models.json`, and each profile in `profiles.json`, that has no agent definition discoverable from the current workspace (project + global), reusing the existing `unmatchedProfileKeys` comparison." (issue #2629, Proposed outcome)
S2. "Unconditionally excludes the provider review roles (`PROVIDER_REVIEW_ROLES`: `review-refuter`, `review-validator`) from the candidate list, since those keys are live routing targets with no agent file by design (see #2430) and must never be offered for removal." (issue #2629)
S3. "Lets the user select which of the remaining stale keys to delete, and only deletes the ones explicitly selected, across all three stores, atomically, with no automatic or implicit deletion anywhere else (startup, sync, or save)." (issue #2629) — clarified 2026-10-28 (L2): "atomically" scopes to the single explicit confirm action (deletes exactly the checked keys, nothing more, nothing on a later unrelated save/sync) and to each store's own existing write guarantee (profiles.json's temp-file-plus-rename, models.json's and subagents.json's existing direct-write). It does not require a new cross-file transaction or rollback mechanism; none exists anywhere else in this codebase today and inventing one is out of scope. Write sequentially through the three existing paths; if one write throws, stop and surface the error to the user (do not swallow it, do not silently continue to the next store) rather than retrying or rolling back prior successful writes.
S4. Out of scope: do not change the startup warning (`extensions/gentle-agents.ts`) or the panel's existing "unmatched" notice strings (`routingScreenNotices`) — that surface is already claimed by another contributor for issue #2430. Only add the new opt-in cleanup action and its own write path.
S5. Keep each PR ≤400 changed lines (chained-pr skill): PR1 is pure lib logic + unit tests (no UI); PR2 wires PR1's functions into the TUI panel + its own tests.
