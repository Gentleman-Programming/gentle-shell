# Herdr status records (producer only)
Publish Gentle Shell activity as OSC 7501 status sub-records so Herdr Desktop mods (or any OSC 7501 host) can show it. Producer and contract only: no mod, layout or installer. Branch `feat/herdr-status-records` from origin/main 0336985b5; files imported from `feat/herdr-desktop-status-upstream` (96aa9c3ff).
Runner: `node --experimental-strip-types --test tests/<file>.test.ts`; `pnpm typecheck`; `pnpm test`.

## Specs

- S1: "lo que debería viajar a gentle shell no es ninguna personalización, si no sólo los eventos que permitan la personalizacion". The branch contains only the producer: `lib/herdr-desktop-status.ts`, `lib/herdr-desktop-events.ts`, `extensions/gentle-herdr-desktop-status.ts`, the additive emits in `extensions/gentle-agents.ts`, their tests, and docs. No mod, layout, installer command, `verify-package-files` entries or Spanish UI text.
- S2: Remove the `decision` record (and its `herdr:blocked` / attention-bus input) from the producer: once upstream PR #3216 merges, the root status already reports `blocked` while `ask_user_question`/`ask_user_choice` wait. Root status stays owned by Pi and `gentle-program-identity`; this extension never writes the root record.
- S3: Subagent records are named `subagents/<taskId>` instead of `sub/<taskId>` (decision: "subagents/<task> (Recomendado)"), matching pi-subagents. Everything else about them is unchanged: title = task label (agent name fallback); `working` for queued/running; `blocked:kind=question` with msg `waiting for user` (child waits on the user) or `question for parent` (unanswered child query; takes precedence).
- S4: Failure records (decision: "Sí, en este PR"). When a background job (`bg/<jobId>`) ends in failure (non-zero exit code or `failed` status; see L3) or a subagent task (`subagents/<taskId>`) ends `failed` or `timed_out`, the record is re-sent with the same id as `state=error`, keeping its title, with msg `exited <code>`, `failed` or `timed out` as applicable, and is cleared automatically after 60 seconds (`ERROR_TTL_MS = 60000`), or earlier on session shutdown/replacement. A `stopped` job (user `job_stop`, or a `monitor` reaching its mandatory `timeout_seconds`, which is its normal end) or a cancelled subagent is not a failure: cleared at once as today. Successful completion: cleared at once as today. If the jobs snapshot cannot tell failure from success, report it instead of guessing.
- S5: Gating unchanged: only with `HC_TERMINAL_ID`, `PI_PROGRAM_STATUS_APP=gentle-shell`, interactive TUI, not a delegated child (`GENTLE_PI_AGENTS_CHILD` unset). Records are cleared on shutdown/replacement; text base64, control-free, capped at 512 bytes; unsafe id segments hashed `h-…`.
- S6: Docs (`docs/gentle-shell.md`, English) describe the records as a contract for third-party mods: a table of every id, state, kind, title/msg values and lifecycle (`todo`, `bg/<jobId>`, `subagents/<taskId>`, `wait/<target>`, `sent/<target>`, `ask/<peer>`, plus the `error` variants of S4), the gating, the 512-byte cap, hashed segments, and that the msg strings listed are part of the contract. No install command, mod or layout text. `docs/readme-reference.md` gets a short pointer without installer text.
- S7: No `ctx` record (decision: "Remove ctx record"). Review (Alan-TheGentleman): "Can we keep `ctx` out of the Agents panel’s activity rollup while still publishing the context percentage? [...] a pane with only `ctx` can look busy indefinitely. [...] add a regression test: `ctx` alone leaves the pane idle, while an active background job still makes it show as working." herdr-core accepts progress only with working/blocked (L7), so the producer stops publishing `ctx`; known context usage alone writes nothing, a running job still writes `bg/<jobId>` as `working`.
- S8: CodeRabbit A (decision: "Fix A and B"): "If the transport changes while `sendNotification` awaits its acknowledgement, the peer can accept the message before this check returns `error: \"stale\"`. The caller loses the accepted message ID and can send a duplicate if it retries. Use the transport check only to suppress the display event. Return the accepted receipt with the original sender identity. Add a test that replaces the transport before resolving an accepted send."
- S9: CodeRabbit B: "If an expiry clear throws once, `publish` has already removed the expired send or error. `arm` then finds empty TTL maps and schedules no retry. The terminal record remains after writes recover. During `close`, the same failure discards the remaining cleanup operations when ownership is removed. Retain pending terminal writes across expiry and teardown. Reconcile pending clears with replacement records so a delayed clear cannot remove a replacement record."
