# Installer: pinned Go alongside when Go is missing or older
Objective: the browser installer provides its own pinned, verified Go toolchain (official go.dev archive, SHA-256 pinned) when a build needs Go and the user's Go is missing or older, used only for building and never modifying the user's system.
Branch: feat/installer-pinned-go (from origin/main 327fed947). Delivery: single PR, merge with green CI after independent verification, then regenerate the v4.0.0 double-click installers. Test runner: `node --experimental-strip-types --test tests/<file>.test.ts`.

## Specs
- S1. User (verbatim): "puede usar homebrew para instalar go y demas?" then "deberiamos de instalarselo al user no?" and chose "Sí, copia fijada de Go al lado": when Go is needed (main channel on every platform; Windows release build, where gentle-pi's postinstall may build Gentle AI from source) and the user's Go is missing or older than the requirement (GENTLE_AI_WINDOWS_MINIMUM_GO_VERSION, currently 1.25.10), the installer acquires a pinned Go instead of blocking.
- S2. Integrity: the official go.dev archive for the platform (darwin-arm64, darwin-amd64, linux-amd64, linux-arm64, windows-amd64), pinned by exact version and SHA-256 taken from go.dev's published checksums; same safety as the existing Node/pnpm acquisitions (verified bytes before use, safe extraction without links/traversal, no-replace publication into a private installer-owned directory, fail closed on any mismatch).
- S3. No system changes: the user's Go (Homebrew, mise, official pkg, anything) is never modified or removed and the user's PATH/profile is not edited for Go; the pinned Go is used by the installer's build steps by absolute path / child environment only. A Go meeting the requirement is reused as today.
- S4. Consent: the plan shown before consent says that Go <version> will be downloaded and verified only to build, with the found version (or "missing") and that the user's system is unchanged. Nothing is downloaded before consent unless the existing bootstrap model requires it — decide with evidence and state it.
- S5. Later builds: `gentle-shell upgrade --channel main` (and any later step that needs Go for the same installation) can use the installer's pinned Go when the user's Go is missing/older, or the behavior is documented explicitly if out of scope.
- S6. No regression: release installs that do not need Go never download it; Node/pnpm/npm/Pi behavior from #1995/#1988/#1978/327fed947 unchanged; CI installer suites green; docs/README updated (S5 of the previous feature wording "An older Go is not downloaded" changes).
