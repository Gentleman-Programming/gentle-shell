# Installer: Windows parity for version-managed and older tools
Objective: the browser installer on Windows treats Node, npm, pnpm and Pi the way it already does on macOS/Linux: older or version-managed tools no longer block; the user's working tools are reused; missing or older ones get the pinned copy alongside; everything shown before consent.
Branch: feat/installer-windows-parity (from origin/main e06582a2e). Delivery: single PR, merge with green CI (Windows runners run the native tests) after independent verification, then regenerate the v4.0.0 double-click installers. Test runner: `node --experimental-strip-types --test tests/<file>.test.ts`; native Windows tests run only in CI.

## Specs
- S1. User (verbatim): "ahora.... esto quedo asi para todos los sistemas operativos? o solo arreglaste para mac?" then "ahora mismo" for the Windows parity feature covering the four gaps the parent listed.
- S2. Older Node on Windows: `scripts/bootstrap.cmd` acquires the pinned Node (same official verified archive and integrity path used when Node is missing) instead of refusing a stable older version; unknown/prerelease versions keep refusing; the user's Node is untouched; the plan copy matches macOS/Linux.
- S3. User's npm on Windows: a working npm from Node's install, nvm-windows, Volta, fnm, mise or similar is accepted by behavior (stable `--version`, absolute `config get prefix`), without running commands through a shell in a way that allows injection; the installer persists its own npm only when no working npm resolves; the installer-persisted npm keeps its pin.
- S4. Pi on Windows: an older Pi installed globally by npm is attributed to npm and updated with it (as on POSIX); unattributable Pi keeps the alongside install.
- S5. pnpm on Windows in its global/home directory (standalone `pnpm.exe` from the official installer or `@pnpm/exe`, `pnpm self-update`, pnpm 10/11/12 layouts) is recognized like on POSIX: reused when compatible, pinned copy alongside when incompatible, never replaced or downgraded when it lives in the directory the installer persists into.
- S6. Security and no regression: no shell-string execution of user-controlled paths; existing Windows integrity, ACL/storage and wrapper-proof guards stay unless an equivalent behavioral guard replaces them with evidence; macOS/Linux behavior unchanged; CI (including native Windows lanes) green; docs/README updated.
