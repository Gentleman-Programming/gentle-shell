## Specs

S1. User request (verbatim): "revisa e implementa este issue https://github.com/Gentleman-Programming/gentle-shell/issues/2303#issuecomment-6553124058".
S2. Issue contract (verbatim):
```ts
interface McpServerStatus {
  name: string; // matches the `mcp__<name>` namespace
  state: "connecting" | "ready" | "error" | "disabled";
  tools?: number; // registered tool count, when known
  error?: { kind: "auth" | "timeout" | "transport" | "config" | "unknown" };
  since: number; // timestamp of the last state change
}

pi.getMcpStatus(): McpServerStatus[]; // snapshot
pi.onMcpStatusChanged(cb: (all: McpServerStatus[]) => void): Disposable; // event
```
S3. Sanitization (verbatim): "1. **No secrets, ever** — no tokens, headers, URLs with credentials, env values, or auth prompts." "2. **No raw transport errors** — only the closed `error.kind` enum; raw messages may contain hostnames, ports, paths, or provider details and stay behind `/mcp`."
S4. Names and states (verbatim): "3. **Namespace correlation** — `name` matches the `mcp__<name>` namespace from `getAllTools()`, so UIs can join status with the tool inventory they already render." "4. **Stable states** — the state enum is part of the contract; adding states is a minor change, reusing or rewording existing ones is breaking."
S5. Passive reads (verbatim): "5. **Lazy-friendly** — `getMcpStatus()` is cheap and side-effect free and must not trigger connections; events report transitions the runtime already knows about."
S6. Non-goals (verbatim): "Replacing or wrapping `/mcp`; auth and connection management stay exactly where they are." "Per-tool health or latency metrics." "Retrying/reconnect control from extensions — status is read-only in this proposal."
