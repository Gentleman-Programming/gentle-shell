## Specs

- S1: "Gentle Shell sessions report `app: \"gentle-shell\"`, so dashboards can tell Gentle Shell apart from Pi."
- S2: "como una extension". Authorization: "dale vamos co neso". The accepted proposal is recorded in L3; implement the extension, not an upstream Pi fork or dependency patch.
- S3: "A session started with `gentle-shell` shows as agent `gentle-shell` in `hc ls --json`, and a plain `pi` session still shows as `pi`."
- S4: "A test asserts `buildPiInvocation` sets `PI_PROGRAM_STATUS_APP=gentle-shell`." Use that launcher-provided value to activate the extension, rather than relying on Pi to consume it.
- S5: "prueba todo y merge".
- S6: "tengo una idea! y si hacemos una extension de herder para gentel shell y la instalamos si la persona tiene herder?" Authorization: "vamos con eso". Gentle Shell publishes its own Herdr agent identity as the single lifecycle reporter (documented custom-agent route: own `--source`, own `--agent`), replacing the launcher-injected `herdr:pi` bridge only where Gentle Shell controls loading. Nothing is installed into Herdr or user profiles. Assumption: resume into Gentle Shell is out of scope on Herdr 0.9.3 (custom resume argv needs 0.10.0+).
