## Specs

- **S1** (extensions/codegraph-first-gate.ts:40, minor): "Wait for all active graph calls before allowing memory reads. If graph calls A and B run in parallel, A's completion sets `credited=true` while B is still active. A `mem_search` call then passes the guard. This violates the requirement that every planned graph call return before memory reads. Track active graph executions. Allow memory reads only after a graph call has completed and no graph execution remains active. Also handle a new graph call after credit was granted."
- **S2** (extensions/codegraph-tools.ts:622,640-642, major): "Stop the search when the caller is already aborted. If the caller aborts during the first daemon attempt, execution still starts warm-up. Both this helper and the CLI fallback then register listeners on an already-aborted signal. Node 24 emits that event only once. The warm-up can consume its budget. The CLI fallback then receives a fresh, non-aborted controller and can run for another 180 seconds. Check `signal.aborted` before starting each stage. Exit after cancellation instead of entering warm-up or CLI fallback. Also initialize the CLI controller from the caller's current abort state."
- **S3** (extensions/codegraph-tools.ts:769-772, minor): "Skip sibling scans in child sessions. An ordinary child in an indexed parent workspace passes this condition. `seedSessionWorktrees` can then seed and sync every absent sibling index. The child readiness gate does not protect this separate call. Add the `CHILD_ENV` check here. Keep the child's own unindexed-worktree initialization in `prepareReadiness`. The child-worktree specification limits sibling pre-warming to parent sessions and says ordinary children still skip entirely."
- **S4** (lib/codegraph-daemon.ts:141, major): "Reject JSON null before dispatching MCP replies. If a daemon sends `null\n`, this cast returns `null`. The socket callback then reads `message.codegraph` and throws outside the promise's error handling. Node normally terminates on that uncaught callback exception. The stdio warm-up has the same failure through `mcpReplyKind`. Validate that the parsed value is a non-null reply object. Return `undefined` for other JSON values, and test both transports."
- **S5** (lib/codegraph-lease.ts:82-84, major): "Check the adopted writer before reclaiming a dead launcher's token. On POSIX, the detached init child can survive its launcher. During startup, the child may not have created `codegraph.lock` yet. Although `adoptWriterPid` records that child, this verdict ignores `writerPid` when `writerProxy` is false. The dead launcher therefore makes the token stale while its init child remains alive. Another session can start a second init. Retain the token while its adopted direct writer is alive."
- **S6** (lib/codegraph-lease.ts:136-144, major): "Make stale-token replacement atomic across reclaimers. If two sessions read the same stale token, the first session can remove it and create a new token before the second session reaches this line. The second session then removes the first session's live token. Both exclusive creates succeed, so both sessions can run the protected operation. Serialize stale recovery with acquisition. The exclusive create alone does not protect this read/remove/create sequence."
- **S7** (lib/codegraph-lease.ts:145,117-122, major): "Bind release to the acquired token. If this lease expires and another session acquires the path, the old `release` callback removes the new session's token. A third session can then acquire while the new owner still runs. Give each acquisition a unique identity. Make release safe against token replacement, using the same atomic ownership protocol as recovery."
- **S8** (lib/codegraph-lease.ts:149, major): "Keep the sync lease valid for the complete refresh sequence. `daemonlessRefresh` holds this lease across both `unlock` and `sync`. Each command can run for 120 seconds, plus timeout cleanup. This lease lasts only 120 seconds in total. If the lease expires while a command is still starting and has not created `codegraph.lock`, another session can acquire the lease and run `unlock`. Preserve ownership until the entire sequence and cleanup finish. Renew the lease or prevent expiry from displacing its live owner."
- **S9** (lib/codegraph-readiness.ts:110, minor): "Quote Windows shell arguments with cmd.exe rules, not `JSON.stringify`. On Windows, `JSON.stringify` doubles backslashes before `cmd.exe` receives the command. `cmd.exe` keeps those characters inside double quotes. `codegraph.cmd` then forwards them unchanged, so CodeGraph can receive a project argument that differs from `cwd`. For UNC project paths, this can change the path that CodeGraph resolves. Build the Windows command with quoting that preserves backslashes, and keep the POSIX quoting path separate."
- **S10** (lib/codegraph-readiness.ts:349, minor): "Require confirmed absence at the post-lock recheck. If the index becomes inaccessible while readiness waits for seeding or the init lock, `indexState` returns `"unknown"`. This expression still starts `init`, although the tri-state contract permits initialization only for `"absent"`. Handle all three states explicitly. Skip initialization and report failure for `"unknown"`."
- **S11** (lib/codegraph-readiness.ts:376-379, major): "Remove the readiness entry after it is registered, not inside the async body. The `finally` block runs during the IIFE call when the body completes before its first `await` (reload session, `action: "none"`, synchronous exception). In those cases `inFlight.delete(input.cwd)` runs before line 379 stores the settled promise. Nothing removes that entry later. Each later `prepareReadiness` call for the same `cwd` in the same process returns the stale result. Schedule the cleanup with `.finally()` on the registered promise. Add a test that runs a reload for a `cwd` and then a normal startup for the same `cwd`, asserting the second startup runs its sync or init."
- **S12** (lib/codegraph-readiness.ts:516,449-468, major): "Escalate to `SIGKILL` before reporting a timed-out CodeGraph command as failed. On POSIX, `killProcessTree` sends `SIGTERM` only. A Node process that installs a `SIGTERM` listener can keep running after that signal. The grace timer resolves `false` after `KILL_WAIT_MS` without checking that the process exited. The caller then releases the sync lease, so a surviving CodeGraph process can keep writing the index with no lease held. This contradicts the `runCodegraph` doc comment, which states that the pid 'must not outlive the result.' Send `SIGKILL` when the grace period expires. Add a `signal` parameter to `killProcessTree` for this path."
- **S13** (lib/codegraph-seed.ts:112-113,121, major): "Do not follow destination symlinks during automatic seeding. If `.codegraph/.gitignore` points to `../package.json`, this write replaces the worktree's manifest with `INDEX_GITIGNORE`. Node's default write mode truncates an existing file. The sibling scan can reach this write automatically at session start. Reject symlinked destination directories. Create `.gitignore` exclusively when absent, and use safe creation for staged files so existing symlinks cannot redirect writes."
- **S14** (lib/codegraph-seed.ts:133-144, major): "Keep the seed unpublished until validation succeeds. This rename makes `codegraph.db` visible before the validating sync finishes. Another session can return `target-exists`, or receive `present` from `acquireInitLock`, and treat initialization as complete. If validation then fails, this session removes the database that the other session accepted. Validate in an isolated staging directory before publication, or make all readiness consumers wait for the seed owner's completed validation. Holding the init lock alone does not help while its consumers accept an existing database."
- **S15** (tests/codegraph-daemon.test.ts:37,58, minor): "Use a Windows named pipe path for the fake daemon. The fake daemon binds to a filesystem path. The Node IPC documentation requires a Windows IPC path to be in the `\\\\.\\pipe\\` or `\\\\?\\pipe\\` namespace. On Windows, `server.listen` can fail, and the `daemon.ready` promise never resolves. Use a unique pipe name on Windows. Keep the filesystem path on other platforms. This also matches the Windows pipe handling in `lib/codegraph-daemon.ts`."

- **S16** (lib/codegraph-lease.ts:112, major): "Replace the adopted-writer token atomically. `writeFileSync` uses truncating replacement here. If the launcher stops after truncation, the token can remain empty or incomplete. Later calls return `"unknown"` indefinitely, so token expiry cannot restore initialization. Node documents the default write flag as truncating existing files. ([nodejs.org](https://nodejs.org/download/release/v24.11.0/docs/api/fs.html)) Write complete metadata to a temporary file on the same filesystem. Replace the token under the ownership protocol only after the write succeeds. Based on learnings, shared-state updates must not expose truncated or partially written contents."
- **S17** (lib/codegraph-readiness.ts:84-85 + lib/codegraph-lease.ts:297, major, heavy): "Record the sync child PID on the sync lease. On POSIX, the sync child is spawned with `detached: true`. The launcher PID becomes the only owner recorded in the sync token. If the launcher exits before the child creates `.codegraph/codegraph.lock`, the lease verdict is `held-stale`. Another session can then acquire the lease and run `unlock` while the child still writes. This breaks the invariant stated in `lib/codegraph-lease.ts:80-87`: a live writer is never unlocked under. Pass the sync lease's adoption hook to `runCodegraph`, the same way `acquireInitLock` adopts its init child. `tryAcquireSyncLease` does not return such a hook in the inspected code, so add one before passing it here. Do not pass `undefined`."
- **S18** (lib/codegraph-readiness.ts:342,:393, major): "Skip the daemon warm-up when another session holds the sync lease. When `daemonlessRefresh` returns `held-live`, another session owns the sync lease and can still be running `unlock`. `daemonlessOk` maps that outcome to `ok = true`. The sync branch then still calls `input.warm` (lines 388–391). `warmUpDaemon` checks only daemon liveness and starts `serve --mcp` when no daemon is alive. A daemon started during the other session's `unlock` can lose its writer lock to that unlock. The contract at lines 71–72 names this outcome as the one the lease prevents. Record the `held-live` outcome and stand down the warm-up for it. The `ok` value does not change."
- **S19** (lib/codegraph-seed.ts:159-164, major, heavy): "Validate the seeded index against the target worktree, not the staging project. The validating `sync -q` runs in `stagingRoot`. That directory contains only the copied `.codegraph/` files and no source files. The CodeGraph `sync` command drops tracked entries whose files are missing on disk. The copied database tracks the main checkout's source files, so this sync can remove those entries. It can also exit successfully. The `!synced` check at lines 160-164 would then accept an emptied index, and the seed would publish it as `seeded`. The current tests use a runner that always returns `true`, so they do not cover this path. A check that runs against a project without source files does not prove that the copied index matches the target worktree. The seed needs a validation step that reads the copied index against the target's own files, or that fails when the sync removes entries."
- **S20** (lib/codegraph-mcp-exposure.ts:43,:72, major): "Preserve the original configuration when writing fails. `writeFileSync` uses the default `w` flag, which truncates the existing file before writing. ([nodejs.org](https://nodejs.org/download/release/v22.19.0/docs/api/fs.html)) If the write then fails with `ENOSPC`, this optional update can leave the entire `mcp.json` empty or partial, including sibling server configurations. The next call returns `"unparseable"` and cannot recover the original content. Use an atomic update that preserves existing permissions and symlink behavior. Add a failure-path test that checks that the original file remains intact."
- **S21** (extensions/codegraph-first-gate.ts:61-65, minor): "Grant credit only for query or explore operations. If the native `codegraph` tool completes an `init` operation, this handler grants memory credit without a query or explore. The next `mem_search` passes the gate. Track the requested operation and grant credit only when a query or explore finishes, including failed attempts."
- **S22** (extensions/codegraph-tools.ts:98, minor): "Convert the character limit to a byte budget. If CLI output contains 400,000 CJK characters, it uses about 1,200,000 UTF-8 bytes. This exceeds the new 1,000,000-byte `maxBuffer`, although its character count is below `MAX_REPLY_CHARS`. Node terminates the process before `truncateOutput` can return the bounded result. Use a UTF-8 byte budget that covers the character limit. ([nodejs.org](https://nodejs.org/download/release/v24.0.0/docs/api/child_process.html))"
- **S23** (extensions/codegraph-tools.ts:166-167, minor): "Handle directory-resolution failures before caching these paths. If HOME or the configured temporary directory is missing or inaccessible, these unguarded calls fail during module evaluation. The extension cannot register its tool or startup hooks. Node permits environment overrides for these directories and throws synchronous filesystem errors immediately. Resolve and cache these paths inside the guarded validation path, while preserving fail-closed workspace checks. ([nodejs.org](https://nodejs.org/download/release/v24.0.0/docs/api/os.html))"
- **S24** (extensions/codegraph-tools.ts:609, minor): "Route lazy warm-up through an injectable adapter. If a test workspace has no registered daemon, this call reaches the real `warmUpDaemon` and `spawnCodegraph`. It does this even when the test supplies `daemonExplore`, `warm`, and `syncRun` fakes. The new query tests can therefore start real CodeGraph processes when CodeGraph is installed. Inject lazy warm-up too, and disable it in tests that do not exercise process startup."
- **S25** (extensions/codegraph-tools.ts:716-717, minor): "Reset the per-prompt CodeGraph state at the user-prompt boundary, not on every `turn_start`. In the resolved `@earendil-works/pi-coding-agent` package, `turn_start` fires for every assistant response, including each response that follows tool calls. This handler calls `clearSearchSync()` on each of those events. Within one user prompt, the handler therefore clears the 60-second daemon bypass and re-arms the background sync. A wedged daemon can then go through the full attempt sequence again on later responses in the same prompt, and the background unlock and sync can run again. The comment at line 716 says the sync runs once per user prompt, so the code does not match the stated intent. Move the reset to an event that marks a new user prompt. Account for the fact that retries, queued messages, and compaction can start another low-level agent run within the same prompt. Confirm that the chosen event does not fire between tool-call iterations."
- **S26** (extensions/codegraph-tools.ts:730, minor): "Honor the override in a leading command assignment. If the command is `GENTLE_CODEGRAPH_ALLOW_INDEX=1 codegraph index`, the detector removes the assignment and recognizes the rebuild. This check reads only the parent process environment, so it still blocks the explicit override. Recognize the literal leading override assignment, or state that the variable must be set in Gentle Shell's launch environment."
- **S27** (tests/codegraph-lease.test.ts:359, minor): "Hold the winning lease until the other child finishes its attempt. The marker barrier runs before the dynamic import. If the second child takes more than 200ms to reach `tryAcquireLease`, the first child releases the lease first. The second child then correctly acquires it, but Line 373 fails the test. Use an attempt-completed handshake instead of a fixed hold duration. Keep the winning lease until the other child records its result."
- **S28** (lib/codegraph-mcp-exposure.ts:78, minor): "Isolate failures between agent homes. If the pi config is readable but not writable, its exposure update throws and stops `map`. The writable Gentle Shell config is never visited. Repeating the operation encounters the same failure. Handle I/O failures per path so the second home still receives its update. Add a test where the first write throws and the second write succeeds."
- **S29** (tests/codegraph-mcp-exposure.test.ts:85,91-93, minor): "Use platform-native paths in the test expectations and fixture keys. `codegraphMcpPaths` builds paths with `join` from `node:path`. On Windows, `join` returns `\`-separated paths. ([nodejs.org](https://nodejs.org/download/release/v22.19.0/docs/api/path.html)) The expectations and fixture keys in this file use `/`. The assertion on line 85 therefore fails on Windows. In the multi-home test, the `files` lookups miss, so both homes are not added, and `files[path]!` reads `undefined`. Build the expected paths with `join`. Use the same helper for the fixture keys. On POSIX, these values match the current strings. Add `import { join } from "node:path";` to the test file if it is not already imported."
- **S30** (tests/codegraph-seed.test.ts:193, minor): "Write a newline between child validation records. The outer string converts `\\\\n` into `\\n` in the generated script. That script appends literal backslash-n characters, not a newline. If both children validate, Line 211 still sees one line and the test passes. Change the outer string to use `\\n`. This makes the assertion reject two validation records."
