## Specs

- **S1** (extensions/codegraph-first-gate.ts:40, minor): "Wait for all active graph calls before allowing memory reads. If graph calls A and B run in parallel, A's completion sets `credited=true` while B is still active. A `mem_search` call then passes the guard. This violates the requirement that every planned graph call return before memory reads. Track active graph executions. Allow memory reads only after a graph call has completed and no graph execution remains active. Also handle a new graph call after credit was granted."
- **S2** (extensions/codegraph-tools.ts:622,640-642, major): "Stop the search when the caller is already aborted. If the caller aborts during the first daemon attempt, execution still starts warm-up. Both this helper and the CLI fallback then register listeners on an already-aborted signal. Node 24 emits that event only once. The warm-up can consume its budget. The CLI fallback then receives a fresh, non-aborted controller and can run for another 180 seconds. Check `signal.aborted` before starting each stage. Exit after cancellation instead of entering warm-up or CLI fallback. Also initialize the CLI controller from the caller's current abort state."
- **S3** (extensions/codegraph-tools.ts:769-772, minor): "Skip sibling scans in child sessions. An ordinary child in an indexed parent workspace passes this condition. `seedSessionWorktrees` can then seed and sync every absent sibling index. The child readiness gate does not protect this separate call. Add the `CHILD_ENV` check here. Keep the child's own unindexed-worktree initialization in `prepareReadiness`. The child-worktree specification limits sibling pre-warming to parent sessions and says ordinary children still skip entirely."
- **S4** (lib/codegraph-daemon.ts:141, major): "Reject JSON null before dispatching MCP replies. If a daemon sends `null\n`, this cast returns `null`. The socket callback then reads `message.codegraph` and throws outside the promise's error handling. Node normally terminates on that uncaught callback exception. The stdio warm-up has the same failure through `mcpReplyKind`. Validate that the parsed value is a non-null reply object. Return `undefined` for other JSON values, and test both transports."
- **S5** (lib/codegraph-lease.ts:82-84, major): "Check the adopted writer before reclaiming a dead launcher's token. On POSIX, the detached init child can survive its launcher. During startup, the child may not have created `codegraph.lock` yet. Although `adoptWriterPid` records that child, this verdict ignores `writerPid` when `writerProxy` is false. The dead launcher therefore makes the token stale while its init child remains alive. Another session can start a second init. Retain the token while its adopted direct writer is alive."
- **S6** (lib/codegraph-lease.ts:136-144, major): "Make stale-token replacement atomic across reclaimers. If two sessions read the same stale token, the first session can remove it and create a new token before the second session reaches this line. The second session then removes the first session's live token. Both exclusive creates succeed, so both sessions can run the protected operation. Serialize stale recovery with acquisition. The exclusive create alone does not protect this read/remove/create sequence."
- **S7** (lib/codegraph-lease.ts:145,117-122, major): "Bind release to the acquired token. If this lease expires and another session acquires the path, the old `release` callback removes the new session's token. A third session can then acquire while the new owner still runs. Give each acquisition a unique identity. Make release safe against token replacement, using the same atomic ownership protocol as recovery."
- **S8** (lib/codegraph-lease.ts:149, major): "Keep the sync lease valid for the complete refresh sequence. `daemonlessRefresh` holds this lease across both `unlock` and `sync`. Each command can run for 120 seconds, plus timeout cleanup. This lease lasts only 120 seconds in total. If the lease expires while a command is still starting and has not created `codegraph.lock`, another session can acquire the lease and run `unlock`. Preserve ownership until the entire sequence and cleanup finish. Renew the lease or prevent expiry from displacing its live owner."
- **S9** (lib/codegraph-readiness.ts:110, minor): "Quote Windows shell arguments with cmd.exe rules, not `JSON.stringify`. On Windows, `JSON.stringify` doubles backslashes before `cmd.exe` receives the command. `cmd.exe` keeps those characters inside double quotes. `codegraph.cmd` then forwards them unchanged, so CodeGraph can receive a project argument that differs from `cwd`. For UNC project paths, this can change the path that CodeGraph resolves. Build the Windows command with quoting that preserves backslashes, and keep the POSIX quoting path separate."
- **S10** (lib/codegraph-readiness.ts:349, minor): "Require confirmed absence at the post-lock recheck. If the index becomes inaccessible while readiness waits for seeding or the init lock, `indexState` returns `"unknown"`. This expression still starts `init`, although the tri-state contract permits initialization only for `"absent"`. Handle all three states explicitly. Skip initialization and report failure for `"unknown"`."
- **S11** (lib/codegraph-readiness.ts:376-379, major): "Remove the readiness entry after it is registered, not inside the async body. The `finally` block runs during the IIFE call when the body completes before its first `await` (reload session, `action: "none"`, synchronous exception). In those cases `inFlight.delete(input.cwd)` runs before line 379 stores the settled promise. Nothing removes that entry later. Each later `prepareReadiness` call for the same `cwd` in the same process returns the stale result. Schedule the cleanup with `.finally()` on the registered promise. Add a test that runs a reload for a `cwd` and then a normal startup for the same `cwd`, asserting the second startup runs its sync or init."
- **S12** (lib/codegraph-readiness.ts:516,449-468, major): "Escalate to `SIGKILL` before reporting a timed-out CodeGraph command as failed. On POSIX, `killProcessTree` sends `SIGTERM` only. A Node process that installs a `SIGTERM` listener can keep running after that signal. The grace timer resolves `false` after `KILL_WAIT_MS` without checking that the process exited. The caller then releases the sync lease, so a surviving CodeGraph process can keep writing the index with no lease held. This contradicts the `runCodegraph` doc comment, which states that the pid 'must not outlive the result.' Send `SIGKILL` when the grace period expires. Add a `signal` parameter to `killProcessTree` for this path."
- **S13** (lib/codegraph-seed.ts:112-113,121, major): "Do not follow destination symlinks during automatic seeding. If `.codegraph/.gitignore` points to `../package.json`, this write replaces the worktree's manifest with `INDEX_GITIGNORE`. Node's default write mode truncates an existing file. The sibling scan can reach this write automatically at session start. Reject symlinked destination directories. Create `.gitignore` exclusively when absent, and use safe creation for staged files so existing symlinks cannot redirect writes."
- **S14** (lib/codegraph-seed.ts:133-144, major): "Keep the seed unpublished until validation succeeds. This rename makes `codegraph.db` visible before the validating sync finishes. Another session can return `target-exists`, or receive `present` from `acquireInitLock`, and treat initialization as complete. If validation then fails, this session removes the database that the other session accepted. Validate in an isolated staging directory before publication, or make all readiness consumers wait for the seed owner's completed validation. Holding the init lock alone does not help while its consumers accept an existing database."
- **S15** (tests/codegraph-daemon.test.ts:37,58, minor): "Use a Windows named pipe path for the fake daemon. The fake daemon binds to a filesystem path. The Node IPC documentation requires a Windows IPC path to be in the `\\\\.\\pipe\\` or `\\\\?\\pipe\\` namespace. On Windows, `server.listen` can fail, and the `daemon.ready` promise never resolves. Use a unique pipe name on Windows. Keep the filesystem path on other platforms. This also matches the Windows pipe handling in `lib/codegraph-daemon.ts`."
