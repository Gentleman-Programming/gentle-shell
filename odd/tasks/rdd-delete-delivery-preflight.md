# RDD: delete the delivery preflight gate, keep a warning

Remove the blocking RDD pre-delivery gate added by PR #3005 (first shipped in gentle-shell v4.8.0) and replace it with a non-blocking warning.
Branch `refactor/rdd-delete-delivery-preflight` from origin/main 25a965a13.

## Specs

- S1. Delete the blocking gate: `lib/review-delivery-preflight.ts` (`checkReviewDeliveryPreflight`), its call site in `extensions/gentle-ai.ts`, and its tests. No `git push` / `gh pr create` / `gh pr merge` is ever denied by RDD anymore. User decision (verbatim): "Borrarlo y dejar solo un aviso (recomendado)": "Se elimina el gate, el parser de entregas, el registro de rango y el requisito de assess. Queda una regla en el orquestador (revisar antes de entregar) y, como mucho, un aviso cuando el STATUS nativo dice que hay un candidato sin revisar. Se descarta el fail-open."
- S2. Delete what only the gate needed: the session-retained committed-range selector in `lib/review-continuation-registry.ts` (`readCommittedRange` / reminder range retention), the delivery-specific parsing in `lib/destructive-command-guard.ts` (`recognizeReviewDeliveryActions` and helpers) — ONLY if no other feature uses them (grep every caller; destructive-command protection itself stays), the `scripts/verify-package-files.mjs` entry, and docs (`docs/review-delivery-preflight.md`, `docs/readme-reference.md` and any other mention). Every user-facing string that named the gate or its refusals ("RDD pre-delivery: …") must be removed repo-wide (grep the STRING, not just symbols): docs, assets/orchestrator*.md, prompts, skills, tests, help text.
- S3. Warning (non-blocking): when a bash command contains a delivery verb (`git push`, `gh pr create`, `gh pr merge`; a simple word match is enough — false positives/negatives are cheap because it never blocks) and RDD is effectively on, read the native STATUS once for the session cwd; if it reports an unreviewed / unacknowledged due candidate, show one notice through the existing notify channel, e.g. `RDD: this repository has an unreviewed candidate; review it before delivery.` Any failure reading STATUS → no notice, never a denial. The command always runs. Keep it small (target well under 100 lines) — no parser, no range registry, no assess call.
- S4. Orchestrator rule: confirm the orchestrator/skill prompt already says to review the committed candidate before delivery when RDD is on; if not, add one sentence in the place that governs delivery (and update any mirrored copy + its contract tests).
- S5. Previous behavior unrelated to delivery is unchanged: destructive-command guard, sensitive-path guard, review tools, Stop hook reminders. Tests that pinned gate behavior are deleted, not rewritten to assert the opposite; tests of shared helpers that remain keep passing.
