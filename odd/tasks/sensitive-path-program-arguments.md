# Sensitive-path guard: let a program use a secret file the agent does not read

The guard blocks a shell command when a sensitive path is written in it, whether the agent reads the file or only hands it to a program. For everyone, not tied to any profile option.
Branch `fix/sensitive-path-program-arguments`, base origin/main 1f6322cb9, worktree `.worktrees/sensitive-path-program-arguments`. No push, pull request or merge without the user.

## Specs

S1. The rule, in the user's words (L7): «Tiene que ser cualquiera, es que si son comandos bien, los cuales al ejecutarse utilizan de una clave o de un archivo secreto, como puede ser un punto embo, lo que sea, da igual, quedan totalmente igual. Lo que se tiene que justamente evitar es que la gente lea claves y cosas por el estilo, por eso le prohibimos leer archivos, para que no pueda leer las claves que están dentro del archivo.» Confirmed shape: «Sí, con esa regla (Recomendado)»: any command passes, except the ones that read, copy or send the file.

In a shell command (`bash`, `bash_background`, `monitor`), the guard looks at the whole command line, not at its parts (L10). A word that names a sensitive path is blocked when any of these holds:
- any word anywhere in the line names an exposing command, matched by the last path component of the word and ignoring letter case, so `/bin/cat`, `sudo cat`, `CAT`, `env xargs cat` and `$(cat …)` count, whatever comes before or after it. For this check each word is also split at spaces, `$`, `(`, `)` and backticks, and every `\` followed by a line break is removed first, so a reader inside a quoted or glued word counts (`echo "$(cat …)"`, ``echo x`cat …` ``, `bash -c "cat …"`, `eval ". …"`, `ca\`+newline+`t`) (L12);
- any word anywhere in the line, split the same way, is `.` or `source`, and the sensitive path is not an env file whose last path component is the env-file name (L12) (sourcing a key prints its contents in the error messages; sourcing an env file is the allowed way to load it);
- the word is a script, not a path (L13): after the guard's own quote removal, and after setting aside one leading variable reference of the form `$NAME` or `${NAME}` (L14), it still contains whitespace or one of `; | & < > ( ) { } $ ` ' " \`. A sensitive path inside a script given to `bash -c`, `sh -c`, `eval`, `ssh host "…"` or any other program is always blocked, whatever the program, because the guard cannot tell what the script does with it;
- the sensitive path is under an `.ssh` directory (or is that directory) and any word anywhere in the line, split the same way, names a program that creates or writes files there: `install`, `touch`, `ssh-keygen`, `ssh-copy-id`, `mkdir` (L16). Using a key (`ssh -i`, `chmod 600 <key>`) still passes, also when the remote command runs a writer: the word right after `-i` in a segment that starts with `ssh` is exempt from this writer rule only, never from the reader rule (L17);
- the word is a redirection target or in command position, as on base (`< .env`, `> .env`, `.env` as the first word).

Otherwise the word is not blocked, whatever the command is. A line that both uses a secret file and contains a reader somewhere else is blocked as a whole: `docker compose --env-file .env.local logs app | tail -50` is denied, as on base; run the two parts as separate commands, or through the project's make target.

The exposing commands are one list in the code, grouped in a comment by what they do:
- show (`xargs` and `parallel` are here too: they hand file names to another command): `cat`, `tac`, `nl`, `head`, `tail`, `less`, `more`, `bat`, `strings`, `xxd`, `hexdump`, `od`, `base64`, `grep`, `egrep`, `fgrep`, `rg`, `ag`, `sed`, `awk`, `cut`, `sort`, `uniq`, `paste`, `column`, `diff`, `cmp`, `jq`, `yq`, `printenv`, `env`, `wc`, `sha256sum`, `shasum`, `sha1sum`, `md5sum`, `md5`, `zcat`, `zless`, `gsed`, `gawk`, `ggrep`, `openssl`, `find`, `fd`, `xargs`, `parallel`, `gpg`, `sops`, `age`, `ansible-vault`;
- enter: `cd`, `pushd` (the next command reads the file by a name the guard cannot see, L9);
- copy: `cp`, `mv`, `ln`, `dd`, `tee`, `tar`, `zip`, `unzip`, `gzip`, `bzip2`, `xz`, `zstd`, `7z`, `ditto`, `rsync`, `pbcopy`, `xclip`, `wl-copy`;
- send: `scp`, `sftp`, `curl`, `wget`, `http`, `xh`, `nc`, `ncat`, `socat`, `ftp`, `rclone`, `aws`, `gsutil`, `gh`, `git`, `kubectl`;

S5. The docs that describe the guard (`docs/yolo-mode.md`, `docs/permission-modes.md`) state the rule of S1 in a sentence or two and its limit: a program that is not on the list and prints or sends a file is not blocked, and the guard cannot see what a program prints.
