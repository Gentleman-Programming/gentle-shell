## Specs

- S1: Issue #2240 (verbatim problem): "In `/gentle:profiles`, the left pane (profile list) never scrolls; only the right pane (detail) scrolls. With more profiles than visible rows, the excess profiles cannot be seen — and can still be selected invisibly via arrow keys or wheel, since the selection window and the rendered window are independent." Causa verificada: `NativeChoiceList` (lib/native-choice-list.ts) no tiene viewport; `ProfilesPanel.render()` (extensions/gentle-ai.ts) clipea. Arrow keys y wheel mueven `selected` pero la ventana renderizada siempre arranca en línea 0.
- S2: Issue #2189 (verbatim problem): "On a standalone gentle-shell install (running outside pi), the 'Toggle banner text logo' command reports that the text logo is now off, but it does not do what is intended: the setting never takes effect and the startup banner keeps rendering the text logo. The same toggle works as a pi package."
- S3: Issue #2183 (verbatim problem): "`gentle-shell upgrade --channel main` resolves the latest `main` commit of `gentle-shell` and `gentle-ai` through the unauthenticated GitHub REST API (`resolveMainCommit` in `scripts/main-channel.mjs`)... Once the IP's quota is exhausted... the upgrade always aborts with `main-commit-unavailable` (HTTP 403)... even when the user has a valid `GITHUB_TOKEN` in the environment: the fetches do not read it." Fix propuesto en el issue: resolver SHAs de main vía `git ls-remote` en vez de REST API.
